# diff-tour на русском

Локализация [init-co-jp/diff-tour](https://github.com/init-co-jp/diff-tour), основанная на `v0.5.0`.
Ветка форка: `feat/russian-localization`. Лицензия исходного проекта и изменений — MIT.

В интерфейс добавлен русский язык: меню, подсказки, состояния, ошибки и справка.
Генератор пишет экскурсии, вопросы и ответы на русском, сохраняя идентификаторы кода,
имена файлов, команды, ключи JSON и значения перечислений.
Для этого запуска: `tour --lang ru`. Постоянный выбор: `tour setup` → «Русский».
Остальные языки сохранены; справка этой ветки всегда русская.

## Сборка

Нужны Git и Go 1.27.2 или новее:

```powershell
git clone --branch feat/russian-localization https://github.com/3angor/diff-tour.git
cd diff-tour
go build -o tour.exe ./cmd/tour
```

Официальный установщик upstream загружает оригинальную версию и не включает изменения форка.
Готовый установленный CLI модели должен быть доступен через `PATH` и авторизован.

## Codex на Windows: явное включение

В проверенной Windows-среде исходная изоляция чтения одной папкой не поддерживается:
`unelevated` отклоняет split read profile, `elevated` требует чтения `:root`,
а MXC недоступен. Это наблюдение относится к проверенному компьютеру, а не ко всем Windows.

В этой ветке запуск генерации через Codex на Windows по умолчанию завершается
объяснением ограничения. Чтобы явно разрешить совместимый режим для текущего терминала:

```powershell
$env:TOUR_CODEX_WINDOWS_READ_ONLY = '1'
.\tour.exe --repo C:\path\to\your-project --lang ru
```

В этом режиме команды модели **могут читать весь доступный диск**, включая файлы вне
экспортированной копии проекта. Запись файлов и сетевой доступ команд не разрешены.
Используется заранее настроенная Windows-песочница Codex `elevated`; настройка песочницы
и общая конфигурация Codex этим приложением не изменяются. Это не запуск с полным доступом.
Разрешение относится к данной Windows-сессии; другие платформы сохраняют исходный профиль.

Как и исходный diff-tour, генератор использует учётную запись выбранной модели и передаёт
ей код для анализа. Сетевой запрет команд не означает офлайн-генерацию самой моделью.

## Исправление экспорта на Windows

После конца tar-архива остаётся выравнивающий блок. Теперь поток дочитывается перед
ожиданием `git archive`: иначе Git мог заблокироваться на заполненной Windows-трубе.
Также `tour --help` завершает работу успешно.

## Проверки

Проверены все ключи и параметры русских переводов, выбор `ru`, правила языка для
экскурсии и вопросов, разделение языкового кэша, экспорт Git и параметры Codex.
Отдельные тесты проверяют, что чтение всего диска не включается без значения `1`.
Локально через Codex CLI 0.163.0-alpha.11 получены русские экскурсии и проверено
воспроизведение установленной сборкой: учебный пример и изменения рабочего проекта.
Сами экскурсии и исходники других проектов в этот форк не входят.

На Windows полный исходный набор тестов имеет пять известных несовместимостей:

- `TestReadCodexStream`, `TestCommandEvent`: ожидают Unix-пути;
- `TestPrepareCopilotHome`: ожидает Unix-права файла `0600`;
- `TestGeminiOutsideRules`: ожидает Unix-путь в регулярном выражении;
- `TestFindOpenCode`: запускает shell-скрипты без расширения Windows.

Они не исправлялись и исключены только из целевого локального прогона:

```powershell
$env:GIT_CONFIG_COUNT = '1'
$env:GIT_CONFIG_KEY_0 = 'core.autocrlf'
$env:GIT_CONFIG_VALUE_0 = 'false'
go vet ./...
go test -timeout 90s ./... -skip '^(TestReadCodexStream|TestCommandEvent|TestPrepareCopilotHome|TestGeminiOutsideRules|TestFindOpenCode)$'
```

`core.autocrlf` задан только для процессов тестирования, без изменения Git-настроек пользователя.
Полный набор на Linux/macOS для этой ветки локально не запускался.
