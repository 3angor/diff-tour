# tour

[English](README.md) | **日本語**

> 状態: 初期の試作です。ツアーを書く LLM は、いまは [Claude Code](https://claude.com/claude-code) だけに対応しています（ほかの LLM にも対応する予定です）。

AI に頼めば動くコードはできます。でも、なぜそう書いたのかまでは教えてくれません。
`tour` は、変更をシニアエンジニアが読むように案内します。変更がシステム全体の振る舞いをどう変えるのか、どの既存のコードに支えられているのか（変更していないファイルも含めて）、一見冗長な行がなぜあるのか、そしてシニアならどこで「待てよ」と手を止めるのか。

使うキーは基本的に 2 つだけです。**→** で次へ、**←** で戻る。

## 試す

Go 1.27、git、ログイン済みの [Claude Code](https://claude.com/claude-code)（`claude`）が必要です。

```sh
go install github.com/DaiAoki/tour/cmd/tour@latest
cd your-repo
tour
```

初回だけ、2 つのことを聞きます。表示の言語（端末の設定から選び、対応していなければ英語）と、ツアーを作る LLM です。あとから `tour setup` で変えられます。

次に、ツアーにする変更を選びます。いまいるブランチが選ばれているので、Enter を押すだけで始められます。
ツアーを作るには数分かかります。その間、どのファイルを読んでいるかが流れます。できたツアーは保存するので、2 回目からはすぐに開けます。

| コマンド | ツアーにするもの |
| --- | --- |
| `tour` | 選んだブランチ（既定のブランチと比べる） |
| `tour <branch>` | そのブランチ |
| `tour <commit>` | そのコミット 1 つ |
| `tour <base>..<head>` | その範囲 |
| `tour <file>.json` | ツアーのファイル（例: `tours/payment-retry.json`） |

| キー | 動作 |
| --- | --- |
| `→` `space` `enter` | 次の手順へ |
| `←` `backspace` | 前の手順へ |
| `o` | この手順のコードをエディタで開く（`$VISUAL` / `$EDITOR`。`TOUR_EDITOR="code -g {file}:{line}"` のようにも指定できる） |
| `q` | 終了 |
| `↑` `↓` | 手順が画面に収まらないときだけスクロール |

## 手順で見せられるもの

- コードと差分。いつも git から、その時点の実物を読みます。どの言語でも色分けします
- リポジトリに**ない**コード（素直に書いた場合の例、修正案など）。必ずそうだと分かるように示します
- 処理の流れや時系列の図
- 変更前と変更後のデータベースのスキーマ。マイグレーションをメモリ上の SQLite に当てて、実際にできたテーブルを比べます（今は SQLite のマイグレーションだけ）
- データ例の表
- 問い。考えてから次へ進むと、答えが出ます

説明にはすべて、根拠のラベルが付きます。**確かめた**（コード・テスト・コミットメッセージで裏付けがある）、**読み取れる**（コードの構造から言える）、**シニアの見方**（一般的な設計の観点からの解釈。このリポジトリでは確かめていない）。

## 読み取り専用

`tour` は作業ツリーにも `.git` にも書き込みません。

- ツアーを作るときは、変更の前と後のファイルをキャッシュの場所に書き出し、そこで Claude Code を読み取りの道具だけ（`Read`、`Grep`、`Glob`。シェルや Web は使わせない）で動かします。変更のコードは、選んだ LLM に送られます。
- ツアーの時点と作業ツリーの内容が違うファイルを開くときは、キャッシュの場所に読み取り専用のコピーを作って開きます。

## 開発

```sh
go test ./...
go run ./cmd/tour tours/coupons.json --repo path/to/repo --dump --cols 140 --rows 44 --plain
```

`--dump` は全手順を決まった画面の大きさで書き出します。端末なしでレイアウトを確かめるのに使えます。
